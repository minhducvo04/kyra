# Distilling the Agent Specialist — can a local model make Kyra's tool calls?

_Run 2026-09-06 on an Apple M5 Max (36 GB), MLX 0.32 / mlx-lm 0.31.3. Code: `src/companion/agent_ft.py`,
`src/companion/local_tools.py`, `scripts/tool_ft.py`. Plan: `docs/plans/2026-09-06-tool-calling-distill.md`._

## The question

Every `tool` turn today goes to Claude through the real Anthropic tool-use loop, carrying ~2,020 tokens of tool
schemas (measured with the student's own tokenizer: 158-token prompt without them, 2,178 with). `docs/router-model-benchmark.md` (2026-09-02) found Qwen2.5-7B flawless on an 11-case tool suite and
called that too small and too clean to act on. This is the harder suite, the distillation, and the measurement:
can a local model, LoRA-tuned on Claude's own traces, make the same calls with the same arguments - and refuse to
call anything on keyword bait - at $0/turn?

## Method

- **Held-out suite, handwritten first:** `tests/data/tool_testset.jsonl` - 70 cases: 50 that need a tool
  (13 of them need more than one call: find-then-act like "the dentist one is done" where the model must list
  reminders to learn the id, and two-tool asks like "log the application and remind me Friday") and 20 that must
  call nothing (keyword bait such as "remind me how quicksort works", curiosity, chat, and four under-specified
  asks where the right move is a question). Multi-step cases carry scripted listing results so the second call
  has a real id to find. "Today" is pinned to Sunday 2026-09-06 so date arithmetic is checkable. Written before
  any data was generated; never trained on; the generator drops any message that normalizes to a suite message.
- **Scoring:** a case is correct only if the call *sequence* matches (names, in order unless the case allows any
  order), every expected argument matches (exact, or a matcher: `icontains`, `date`, `regex`, `any`), and a
  non-empty reply came back. A no-tool case is correct only if nothing was called. Reported separately:
  over-trigger rate (no-tool cases that called something) and under-trigger rate (tool cases that called nothing).
- **Harness:** `FakeRegistry` serves the *real* tool schemas from `default_tool_registry()`, returns scripted or
  realistic default results, records every call, and raises `TypeError` on missing/unknown arguments exactly as
  the real registry would - so the model sees the same error path Claude does in production.
- **Teacher:** production Sonnet 5 through the real `AnthropicLLM.respond_with_tools` loop against the fake
  registry. Tool schemas now carry `cache_control` (a production change, not harness-only: the schema
  prefix is cached on every tool turn).
- **Student:** `LocalToolLLM` - `LocalLLM` plus the same `respond_with_tools` contract, using the tokenizer's chat
  template to render tools and Qwen's `<tool_call>{json}</tool_call>` wire format. Zero-shot 7B is the baseline.
- **Training data:** messages generated by Claude per category (the 15 tool intents from `router_ft.CATEGORIES`
  plus find-then-act, two-tool, under-specified, and three no-tool buckets), then one teacher trace per message
  with a *varied* "today". A trace is kept only if it agrees with its category (a no-tool message that called a
  tool is dropped and counted; so is a tool message with no call, a missing required argument, or an empty reply).
- **Rows:** mlx-lm's `--mask-prompt` trains only the last message, so each trace becomes one row per assistant
  turn (call → result → call → … → reply), each row carrying the `tools` list the template renders.
- **Bar to activate (set before the numbers):** ≥ 95% of the teacher's suite accuracy and 0 over-triggers.

## Results

| System | Accuracy | Sequence | Over-trigger | Under-trigger | Mean latency | p90 |
|---|---|---|---|---|---|---|
| teacher: Sonnet 5, production tool loop | 92.9% | 92.9% | 5.0% | 6.0% | 3.38s | 5.54s |
| zero-shot Qwen2.5-7B-Instruct-4bit | 78.6% | 84.3% | 5.0% | 8.0% | 2.21s | 3.03s |

**Teacher, the 5 misses** - kept as scored, not re-labelled to fit: two are the draft cases, where it asked for a
background instead of calling `draft_application_material` with none saved (the harness has no profile; declining
to invent is the production-correct move, so a student trained on its traces will inherit the same refusal); one is
"snooze reminder 5 to Wednesday", where it listed first to verify id 5 existed, found the fake list empty, and asked
(a suite artifact - the case scripts no reminders); one under-trigger ("Cursor rejected me :(" got sympathy and an
offer to update, no call); one over-trigger ("what's the news with your day" fetched tech news). The activation bar
is therefore **88.3% accuracy and 0 over-triggers**.

**Zero-shot 7B, where the 15 misses are** (the exact behaviours the distillation has to teach): 6 wrong
sequences - it skipped the listing step and *invented an id* (`complete_reminder(id=1)`, `update(id=1)`) on
find-then-act cases; 4 wrong arguments - weekday arithmetic ("this Friday" → a Tuesday, "the 1st" → a date in the
past, "Wednesday" → tomorrow); 4 under-triggers - all three "I remembered / forgot the X one" review phrasings and
"Cursor rejected me :("; 1 over-trigger - fetched science headlines for "tell me something cool about black
holes". It also saved a CAP-theorem summary as a memory note instead of a learning item.
