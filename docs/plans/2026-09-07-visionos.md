## Before the device arrives - Duc (about 20 minutes of attention, hours of download)

1. **Install Xcode from the Mac App Store now**, tonight if possible - it is a multi-gigabyte download. Open it
   once, accept the licence, and when it offers platforms, tick **visionOS** (the simulator runtime is a second
   download). Then `sudo xcode-select -s /Applications/Xcode.app`. Check: `xcodebuild -showsdks | grep xros`.
2. **Enable Developer Mode on the Vision Pro** when it arrives (Settings → Privacy & Security → Developer Mode) and
   pair it with the Mac over Wi-Fi from Xcode's Devices window. Both on the same network as Kyra.
3. **Set a token**: put `KYRA_API_TOKEN=<something long and random>` in `.env`. The client will carry it.
4. Decide one thing: **does the headset get the applicant profile?** The outline says no by default (the profile
   is the most sensitive record Kyra holds) - the client below never requests it.

## Day one - the client (Duc at the keyboard, Kyra pairing on the code)

Build order, each step runnable in the simulator before the device:

1. **Window, not volume, not immersive** - Apple's guidance is to start with what people recognise. One SwiftUI
   window: a transcript list, a text field, a push-to-talk button as an **ornament** on the bottom edge, the
   backend badge as an ornament on the top. Glass background (system default), targets ≥ 60 pt, nothing in the
   top or bottom band of the field of view.
2. **Transport** - `URLSession` with `waitsForConnectivity`, `Authorization: Bearer <token>`, base URL entered
   once (the Mac's LAN address, or found via Bonjour later). `Info.plist` needs `NSLocalNetworkUsageDescription`;
   without it the first request silently fails on device.
3. **Streaming** - `URLSession.bytes(for:)` and iterate `.lines`, appending each `data:` chunk to the last
   transcript row. This is the one piece worth doing before anything else looks good.
4. **Voice on-device** - `SFSpeechRecognizer` for push-to-talk (six beamforming mics on the headset; note the
   report that it does not work inside the visionOS simulator, so test speech on the device only) and
   `AVSpeechSynthesizer` for replies. Kyra's Kokoro voice stays available through `/api/voice` for consistency;
   on-device wins on latency. `SpeechAnalyzer` (visionOS 26) is the newer API if the deployment target allows.
5. **Presence** - last. A SwiftUI orb whose scale follows the audio level, then a RealityKit
   `ParticleEmitterComponent` in a small volume if it earns it. The rings on the web HUD are the reference.

## What is deliberately not on this list
- Sign in with Apple / OIDC - Phase 2; the bearer token covers one person on one Wi-Fi.
- Sending the applicant profile, documents or autofill to the headset - never requested by the client.
- An immersive space - nothing in Kyra needs to replace the room.
