# The browser HUD

The web front door (`scripts/web_ui.py`, `web/`, the HTTP layer in `webapp.py`): panels, streaming, cancellation, presence, the transcript, layout bugs the browser found.

Entries below were moved verbatim from `CLAUDE.md` on 2026-09-09 (original order kept, newest work is usually nearer the top of each section). Add new entries at the top of this file, dated, with the *why*.

## Entries

- Web UI: `python3 scripts/web_ui.py` → http://127.0.0.1:8420 — a HUD-style browser front end (`web/`). Three-way backend toggle (AUTO/CLAUDE/LOCAL, AUTO is default) in the header, each with its own accent color (violet/cyan/amber); in AUTO mode each Kyra reply shows a small badge with which backend/path actually answered. Same `ConversationManager`/`LLMBackend`/`TurnRouter` underneath, just a third front door alongside `chat.py`/`voice_chat.py`. **Voice now works here too** — a mic button with a PTT/hands-free switch next to the text input (`POST /api/voice`: browser recording → `faster_whisper.audio.decode_audio` → STT → router → TTS → base64 WAV back). Hands-free uses a plain `AnalyserNode` energy-threshold VAD (no external library), paused during playback for the same echo-avoidance reason the CLI is sequential.
- **JOBS panel** (2026-09-03, extended same day) — a slide-in panel (JOBS button, top right) with four tabs, hitting dedicated endpoints directly rather than the chat/router path (a UI button already knows what it wants, no intent to classify):
  - **Draft** — material type, job posting or blank for "ideal role in general", checkboxes to pull background from saved library documents, a style-sample document picker, plus a quick one-off-upload fallback (`webapp.py::job_draft`). Every draft's background also automatically includes whatever Kyra already durably knows about Duc via `memory_notes.py` - the draft tool and general chat now draw on the same "known facts" layer instead of being isolated from each other.
  - **Profile** (new) — an editable form for `profile.py::ApplicantProfile` (name/contact/links/EEO), a **document library** (`job_documents.py::JobDocumentStore` - multiple resumes, style samples, and free-text notes, persisted across sessions instead of the old one-shot-per-draft upload), and a **"View raw record" transparency toggle** showing the exact JSON that autofill/drafting will use - Duc asked for this explicitly, not a nice-to-have.
  - **Tracker** — add/list/change-status, live against the real `job_applications.db`.
  - **Autofill** — URL in, fill-only run against `GreenhouseAutofillEngine`, same fill-never-submit boundary as the chat tool.
  Built fast/functional per Duc's explicit ask ("no need to be nice... we can tweak it later") - not a polish pass, the HUD styling is minimal-but-consistent with the existing token set, not a redesign. One real HTML bug caught building this: a placeholder attribute used backslash-escaped quotes (`\"...\"`), which isn't valid HTML attribute escaping (needs `&quot;` or just avoiding the inner quotes) - the browser silently truncated the placeholder at the first backslash. Caught via a real browser screenshot, not just code review - a reminder that HTML attribute content needs the same "verify visually" discipline as anything else.
- **TOOLS panel** (2026-09-03) — a second slide-in panel (TOOLS button, top right, reuses the same `.jobs-panel`/`.jobs-tab`/`.jobs-btn` CSS classes as the JOBS panel rather than duplicating styles) surfacing reminders/news/science/learning, which existed and worked through chat/voice since early in the project but had no dedicated UI - Duc noticed the gap ("some functionality we done building but not attach to the main UI body") and asked for it connected. Four tabs, same direct-endpoint-not-router pattern as JOBS: **Reminders** (add/list/complete/+1-day-snooze, a "show completed" toggle), **News**/**Science** (fetch button → real RSS results via the existing `TechNewsTool`/`ScienceFactsTool`), **Learning** (due-review list with remembered/forgot buttons, plus a manual add-item form). Real bug caught adding a second header toggle button: `.hud-header`'s content could overflow its container and the page would scroll horizontally to compensate (`html`/`body` had no `overflow-x: hidden`) - fixed by adding that and tightening the toggle buttons' padding at the existing narrow-viewport breakpoint. Verified end-to-end against the real running server and via real browser JS-triggered interaction (not just curl) - reminder add/complete/show-done, live news/science fetches, learning add - all confirmed with no console errors; all test data cleaned from the real `reminders.db`/`learning.db` afterward.
- **Streaming chat + LAN token (2026-09-07)**: `POST /api/chat/stream` is `/api/chat` as SSE (`token` deltas, then `done` with the ChatOut, or `error`); the browser uses it and falls back to `/api/chat`. `KYRA_API_TOKEN` (Settings.api_token), when set, gates `/api/*` for non-loopback callers with `Authorization: Bearer` - the switch that makes `KYRA_HOST=0.0.0.0` (the Vision Pro client) defensible; localhost is never gated. Voice turns use the spoken register: `/api/voice` calls `_answer(..., register="voice")`, which appends `voice_text.SPOKEN_REGISTER` to the system prompt, and `voice_text.spoken_text()` strips markdown before Kokoro sees it (the transcript keeps the written reply). The web HUD now has one presence state machine (`setPresence()` in `app.js`: idle/listening/thinking/speaking/interrupted/failed, stamped on `<body data-presence>` so CSS owns the look, with synthesised earcons on listen-start, reply-start and failure). Plans: `docs/plans/2026-09-07-human-interface.md`, `docs/plans/2026-09-07-visionos.md`.
- **Stopping a reply is two halves, and the browser is the easy one (2026-09-07)**: `POST /api/chat/cancel`. Aborting the fetch only stops the browser *listening* - the turn keeps running on the server and `ConversationManager._record_turn` files the whole reply into history and Chroma, so Kyra would remember saying something Duc never saw and quote it back next turn. Cancellation rides the `on_token` callback the streaming turn already calls per delta: the webapp's wrapper raises `llm.TurnCancelled`, `AnthropicLLM.respond()` catches it, leaves the stream context (which stops the API generating) and returns what was actually said plus `CANCELLED_MARKER` - the same honesty as `TRUNCATION_MARKER`, so a stopped reply can never read back as one Kyra finished. Each turn owns its own `threading.Event` and `_cancel_current` only points at the newest, so a stop pressed a moment too late sets a signal nobody reads instead of killing the turn that just started. In the UI, SEND becomes STOP while a reply streams and the input stays enabled (saying the next thing stops the current reply, and a voice utterance does too); Escape stops, **not** the space bar the plan first sketched, because an enabled input means a space is a space. Only a streamed text turn can be stopped - a tool turn has no `on_token` and runs to completion, which is what you want once a tool has begun doing something real.
- **A SPEAK toggle in the web UI, so a typed turn can be heard too (2026-09-08)** - a voice turn always came back as audio, but a typed one had no way to be spoken, which left half of her reachable only through the microphone. The toggle (beside the mic, off by default, remembered in `localStorage`) posts the finished reply to `/api/speak` and feeds the existing sentence queue. **Two things real use caught that reading would not**: the synthesis stream outlives the audio it has produced, so stopping playback without aborting the fetch lets the queue refill and she starts talking again a moment after being cut off - `interruptPlayback()` aborts it now and each chunk re-checks the toggle rather than trusting the check at the top; and the stale `speaking` presence that left was the symptom that found it. Also removed a duplicate `<link rel="icon" href="data:,">` that arrived from a concurrent session: two icon links is a bug and the blank one wins, so the wordmark glyph stays.
- **The MEMORY tab says what the notes cost, because they are paid on every turn (2026-09-08)** - `GET /api/memory-notes` returns `rendered_chars` and `approx_tokens`, and the tab prints "7 notes · ~1551 tokens on every turn", turning amber past ~2k with "worth pruning". The layer is rendered in full into every system prompt and the design rests on the set staying small; nothing said when it had stopped being small. **The estimate is calibrated, not the chars/4 rule**: a real prompt measured against the API was 6,797 chars for 2,386 tokens, so this content runs about **2.85 chars per token** - dated bullets with markdown are denser than the prose that rule assumes, and chars/4 understated it by a third (1,105 against 1,551). The calibrated figure lands at exactly the 65% share measured independently, which is the cross-check worth keeping: if those two ever disagree again, one of them has drifted.
- **The MEMORY tab: Duc can finally see what Kyra durably believes about him (2026-09-08)** - a fifth tab in the TOOLS panel over `GET/POST /api/memory-notes` and `POST /api/memory-notes/delete`. Memory notes go into **every** system prompt in full and into every resume draft, and until now the only way to read them was to open `data/memory_notes/*.md` - the same transparency gap the PROFILE tab's "view raw record" closed for the applicant profile, and it matters more here because a true-but-irrelevant note has already become a fabricated resume entry once (2026-09-04). `MarkdownMemoryNotesStore` gained `list_notes()` (the same content `render()` gives the model, as rows) and `delete(category, text)`. **Deletion is a deliberate departure, and a narrow one**: the module docstring's append-only rule is about *code* never silently pruning history to resolve a contradiction, and nothing here resolves anything - it removes exactly the line a human clicked, after a confirm. Removing the last note in a category unlinks the file, or a bare `# heading` would keep going into every prompt as a category with nothing under it. Any new `MemoryNotesStore` implementation must supply both methods; they are on the ABC.
- **The favicon 404 was a permanent false positive in every console check (fixed 2026-09-08)** - `web/index.html` now carries an inline `data:` SVG icon (the wordmark's own glyph), so a browser verification that reports a console error means something real. Confirmed by `performance.getEntriesByType("resource")` reporting zero failures on a fresh load.
- **A wrong reply needs somewhere to go, and it is memory notes not the vector store (2026-09-08)**: the web transcript now persists in `localStorage` (restored on load, forgotten by CLEAR) and every Kyra line carries a ✕ that posts to `POST /api/correction`, saving a `corrections` note. Notes are rendered in full into every system prompt, so a correction is in front of her on the very next turn; a Chroma record would only surface when it happened to be semantically similar to something. Two details that are easy to get wrong: `dataset.raw` keeps the reply apart from the meta/interrupted badges that also live inside `.line-text`, so a restore never reads a badge back in as something she said, and a stopped turn never receives the `done` event that would set it, so `markInterrupted` reads the partial back off the painted text nodes or a restored transcript shows an interruption with nothing before it.
- **The phone layout was broken, not cramped, and the cause was min-content (2026-09-08)**: `.header-controls` held a min-content width of 616px, so at 375px the header and the stage were pushed off *both* edges - wordmark, line tags and the mic button all clipped away - while `overflow-x: hidden` hid the evidence. The fix is `flex-wrap` on the header and the input bar, not more hiding: the previous narrow rule had hidden the PTT/HANDS-FREE toggle to buy room, which is the wrong trade on the one device that is all microphone. When a row does not fit on a phone, wrap it and check `document.documentElement.scrollWidth` against `clientWidth` - a clipped layout looks fine in a screenshot right up until the moment you notice the left edge is missing.
- **Browser audio format decoding reuses faster-whisper's own utility** (`companion.voice.decode_uploaded_audio` → `faster_whisper.audio.decode_audio`, which bundles PyAV/ffmpeg) instead of adding a new audio-decoding dependency - handles whatever `MediaRecorder` produces (webm/opus, etc.) without the web UI needing to know or care about the exact format.
- **The web UI's hands-free voice is a plain energy-threshold VAD** (`AnalyserNode.getByteTimeDomainData`, RMS against a fixed threshold, in `web/app.js`), not Silero like the CLI - no external JS library, good enough for a first version, may need real threshold tuning once actually used with real background noise. Paused during TTS playback for the same echo-avoidance reason `voice_chat.py` is sequential - don't remove that guard to make it feel more "always on."
